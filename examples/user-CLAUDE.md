# 사용자 레벨 CLAUDE.md 예시

이것은 사용자 레벨 CLAUDE.md 파일 예시입니다. `~/.claude/CLAUDE.md`에 배치하세요.

사용자 레벨 설정은 모든 프로젝트에 전역으로 적용됩니다. 다음 용도로 사용하세요:
- 개인 코딩 선호도
- 항상 적용하고 싶은 보편적인 규칙
- 모듈화된 규칙 링크

---

## 핵심 철학

당신은 Claude Code입니다. 저는 복잡한 작업에 전문화된 에이전트와 스킬을 사용합니다.

**주요 원칙:**
1. **에이전트 우선**: 복잡한 작업은 전문 에이전트에 위임
2. **병렬 실행**: 가능할 때 여러 에이전트와 Task 도구 사용
3. **실행 전 계획**: 복잡한 작업에는 Plan Mode 사용
4. **테스트 우선**: 구현 전에 테스트 작성
5. **보안 우선**: 보안에 절대 타협하지 않음

---

## 모듈화된 규칙

상세 가이드라인은 `~/.claude/rules/`에 있습니다:

| 규칙 파일 | 내용 |
|-----------|----------|
| security.md | 보안 검사, 시크릿 관리 |
| coding-style.md | 불변성, 파일 구성, 오류 처리 |
| testing.md | TDD 워크플로우, 80% 커버리지 요구사항 |
| git-workflow.md | 커밋 형식, PR 워크플로우 |
| agents.md | 에이전트 오케스트레이션, 에이전트 선택 가이드 |
| patterns.md | API 응답, 리포지토리 패턴 |
| performance.md | 모델 선택, 컨텍스트 관리 |

## 사용 가능한 에이전트

`~/.claude/agents/`에 위치:

| 에이전트 | 목적 |
|-------|---------|
| planner | 기능 구현 계획 |
| architect | 시스템 설계 및 아키텍처 |

| code-reviewer | 품질/보안 코드 리뷰 |
| security-reviewer | 보안 취약점 분석 |
| build-error-resolver | 빌드 오류 해결 |
| e2e-runner | Playwright E2E 테스트 |
| refactor-cleaner | 데드 코드 정리 |
| doc-updater | 문서 업데이트 |

## 개인 선호도

### 코드 스타일
- 코드, 주석, 문서에 이모지 금지
- 불변성 선호 - 객체나 배열을 절대 변경하지 않음
- 적은 수의 큰 파일보다 많은 수의 작은 파일
- 일반적으로 200-400줄, 파일당 최대 800줄

### Git
- Conventional commits: `feat:`, `fix:`, `refactor:`, `docs:`, `test:`
- 커밋 전 항상 로컬에서 테스트
- 작고 집중된 커밋

### 테스팅
- TDD: 테스트 먼저 작성
- 최소 80% 커버리지
- 중요 흐름에는 Unit + Integration + E2E

## 성공 지표

다음과 같을 때 성공입니다:
- 모든 테스트 통과 (80%+ 커버리지)
- 보안 취약점 없음
- 코드가 읽기 쉽고 유지보수 가능함
- 사용자 요구사항 충족
